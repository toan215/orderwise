## Issues

### Issue #1 — Câu hỏi thông tin bị phân loại sai intent (PLACE_ORDER thay vì ASK_FAQ) — Medium
- **Category:** Functional / Content
- **URL:** `/chat/demo-shop` (web-chat API)
- **Mô tả:** Câu hỏi "chính sách đổi trả thế nào" được `extract()` phân loại thành `intent=PLACE_ORDER` thay vì đưa vào nhánh RAG trả lời (ASK_FAQ). Kết quả AI không trả lời nội dung policy, mà hỏi lại "bạn muốn mua gì" (clarification). Trong lúc thử, KHÔNG tạo đơn bậy — nhánh tạo đơn vẫn an toàn (rawLines không resolve được → clarification).
- **Steps:** gửi "chính sách đổi trả thế nào" qua API sau khi đã chat 1 tin trong cùng hội thoại → nhận `intent=PLACE_ORDER`, `orderId=null`.
- **Expected:** `intent=ASK_FAQ` → trả lời policy qua RAG.
- **Actual:** `intent=PLACE_ORDER`, orderId null, AI hỏi lại làm rõ.
- **Root cause (đã soi code):** `apps/api/src/ai/llm/mock.provider.ts` — `looksLikeOrder()` là quy tắc regex do mock tạo, đánh dấu nhầm một số câu hỏi FAQ thành đơn. Với LLM thật (provider kèm system prompt `ASK_FAQ/ASK_CATALOG` nếu chỉ hỏi thông tin) hành vi này sẽ đúng hơn; đây chủ yếu là giới hạn của mock. Cần cải thiện quy tắc mock hoặc dùng intent gate chặt hơn vì mock là mode demo chính khi không có API key.
- **Ảnh hưởng đồ án:** trực tiếp vào **RQ1** (độ chính xác phân loại intent) và chất lượng demo RQ3.

### Issue #2 — Slug shop không tồn tại → hiển thị JSON lỗi thô cho khách — Medium
- **Category:** UX / Content
- **URL:** `/chat/khong-co-shop`
- **Mô tả:** Widget không validate slug khi tải; khi khách gửi tin nhắn, API trả 404 và UI hiển thị nguyên văn `{"message":"Shop not found","error":"Not Found","statusCode":404}` trong bong bóng.
- **Steps:** mở `/chat/khong-co-shop` → nhập "hello" → gửi.
- **Expected:** thông báo thân thiện ("Không tìm thấy cửa hàng") hoặc redirect/404 page; không lộ JSON.
- **Actual:** bong bóng SYSTEM show chuỗi JSON thô.
- **Root cause:** `apps/api/src/web-chat/web-chat.service.ts` ném `NotFoundException`; widget `page.tsx` bắt lỗi và render nguyên `e.message`. Cần bắt lỗi 404 riêng ở client + trả thông báo tiếng Việt.

### Issue #3 — i18n chưa đầy đủ (một số nội dung vẫn tiếng Việt khi chuyển EN) — Low
- **Category:** Content / UX
- **URL:** toàn web admin
- **Mô tả:** Chuyển ngôn ngữ EN→VI cập nhật các nhãn chrome (sidebar, heading, button) nhưng một số nội dung dữ liệu (tên khách "Khách demo", text trạng thái đơn) vẫn tiếng Việt.
- **Expected:** mọi label chuẩn chuyển ngôn ngữ.
- **Actual:** chỉ label chrome chuyển, nội dung data để nguyên.
